# MVP 0.2.0 test build

Scope: repository-only test branch, no deployment, payments, backend changes,
App Store submission, or production diagnosis claims.

## Implemented behavior

- Microphone capture consumes mono 16 kHz PCM in memory and discards chunks.
  It retains only sample/activity counts, never uploads audio, and distinguishes
  silence/insufficient input from audible activity. It never infers a cry cause.
  No validated analysis backend exists in this repository; interpretation stays
  unavailable for all recordings. The activity threshold is an MVP heuristic,
  not a clinically validated cry detector.
- Capture cancels on tab changes, Doctor entry and app backgrounding. Startup,
  permission, stream and cleanup errors are reported; retries are available.
- Child gender is saved with the existing profile. Girls use pink, boys light
  blue. The palette button changes gender for existing users without erasing
  their profile. JSON and earlier pipe-delimited profiles remain readable.
- The original consent notice appears once per browser/device storage profile.
  Existing valid profiles imply prior consent. Clearing local storage resets it.
- Emergency hospital search requests location on demand, times out after 12
  seconds, opens a Maps search with coordinates, and offers a no-location search
  and copyable link. Safari navigation uses the same tab to avoid blocked popups.
  Map results are external listings, not verified provider recommendations.
- The test app URL with `?mode=doctor` opens Doctor-only entry without loading
  the child profile. Exiting returns to a Doctor entry screen, not parent features.
  Doctor mode has an isolated route with no parent navigation or automatic Back
  button. System route-back is disabled; explicit exit requires confirmation.
  Name and specialist/consultant title are stored locally and editable. Profile
  entry rejects numeric contact information and email addresses. A contact-sharing
  policy acknowledgement is required. Calls, verification, account enforcement,
  phone-sharing detection and payments are not enabled. This is not an OS kiosk.
- Existing reassurance fields and vaccine placeholders remain. Tabs now retain
  their widget state so temporary reassurance entries survive tab switches.

## Automated validation

The `MVP test build (no deployment)` workflow runs analyzer, regression tests,
and a release web build, then uploads `baby-monitor-mvp-web` as a GitHub Actions
artifact. It has read-only repository permissions and no deployment job.
The current `main` publishing workflow is unchanged; do not merge without
approval because a merge to main would publish the web app.

## Device acceptance checklist (not yet verified on a physical iPhone)

Use an HTTPS test host or local development environment; iPhone Safari will not
allow microphone/geolocation capture from an arbitrary insecure HTTP address.

1. New local profile: accept notice, choose girl/boy, save. Restart and confirm
   theme/profile persistence and no repeat consent prompt. Change gender with
   the palette button and verify immediately and after restart.
2. Allow microphone: record silence and confirm no result. Record audible input:
   confirm detected activity, cleanup and analysis-unavailable message. No cry
   category or medical diagnosis should appear. Deny microphone and retry after
   changing browser permission. Cancel, switch tabs, enter Doctor mode, and
   background Safari during recording; confirm microphone indicator stops.
3. Maps: allow location, deny location, disable location, and test a slow location
   response. Confirm map search or fallback link is available. Return via browser
   Back to the app. No location request should happen at startup.
4. Doctor: enter a name and title, acknowledge policy, save, edit and reopen.
   Try numbers/email in name, route Back, explicit cancel/confirm exit, and small
   screens/keyboard. Confirm no parent tabs, call or payment controls appear.
5. Reassurance: type a note, change tabs and return; note should remain during
   the session. Vaccine placeholders, Arabic layout and logo should remain.

## Native limitation

The existing iOS scaffold is incomplete. This deliverable targets the Flutter
web MVP; no signed IPA, TestFlight build or physical-device verification is
claimed. Native microphone and location permission descriptions are included.
